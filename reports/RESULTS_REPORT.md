## 3. 第一问模型及试算口径

采用144个10分钟区间，原始时标00:10—次日00:00暂解释为此前区间的平均功率标签，电量为功率除以6。购电量q、交流侧充电量c、放电量d和未利用电量s非负，单位均为kWh。

目标为最小化Σπq；每段满足：

```text
q[t] + PV[t] + d[t] = Load[t] + c[t] + s[t]
E[t+1] = E[t] + 0.9*c[t] - d[t]/0.9
1200 <= E[t] <= 10800
0 <= c[t], d[t] <= 5000/6
c[t] <= (5000/6)*z[t]
d[t] <= (5000/6)*(1-z[t]), z[t]为0/1变量
E[0] = E[144] = 6000
```

没有卖电收益；允许未利用电量。主口径充、放电效率各90%，意味着往返效率81%。LP松弛去掉充放电互斥二进制约束，用于给出下界，不能据此一般性断言所有算例都无需互斥约束。

## 6. 正式结果前必须处理的边界

1. **时间映射**：附件5的result1首段是0:10—0:20，最后一段跨到次日0:10，其他模板也有类似标签问题，与全天00:00—24:00不一致。目前仅在派生CSV中采用连续144段，原模板未改。
2. **费用口径**：问题3下调是否退回原计划电费，模板没有消除歧义。主报告保留“原计划照付＋下调罚费”与“退回取消电量电费＋罚费”两种台账。前者在允许免费弃电时通常使主动下调缺乏经济动机，不能套用后者收益。
3. **可用信息**：问题2、4不得用当天实测未来负载/PV/价格制定0时计划；问题3只能用截至决策时已经发布的预测。完美信息最优值只能用作下界。
4. **跨日状态**：全年调度SOC连续传递，不能每日重置6000 kWh；问题1的日末闭环不直接套用于全年每一天。
5. **模板扩展**：附件5充放电、紧急购电中的日期和省略号是示例，不是输出行数上限。正式结果需覆盖2月1日—12月31日334天，并核对全天合计与费用。

## 9. 第二问：全年可行基线

### 9.1 实现方法与运行范围

实现“负载周滞后/PV日滞后预测＋确定性日前MILP＋计划SOC追踪与实时补偿”。日前购电量一经确定不再修改。初始储能6000 kWh，从1月1日连续运行至12月31日；首日零普通购电冷启动，一月仅作预热。

物理参数为单向效率各90%、SOC范围1200—10800 kWh、单向功率上限5000 kW。末端项为[min(π)/0.9]×|E末−6000|，只进入优化目标，不计入实际电费。主程序默认运行365天，求解限时60秒、相对gap容差0.001、单线程和随机种子0。实时控制假设区间内可快速测量补偿，以10分钟电量近似；不提前读取下一时段真值。

本轮未实现误差场景优化、日内MPC重优化或比较策略，不能将第5节讨论的未来增强模型写成已实现算法。

### 9.5 冷启动与末端处理的实际影响

首日因无历史，普通购电为0；应急购电92035.17 kWh、费用366613.57元。整个一月普通费1470195.59元、应急费771212.16元，均不计入正式总费。一月运行使2月1日SOC为1200 kWh，因此正式期初并非6000 kWh；这一状态来自实际预热，而非人为重置。尚未做不同冷启动策略的影响对照，不能声称预热已经消除全部启动影响。

**末端软惩罚未实现预期储备效果。** 正式334天的计划末端SOC全部为1200 kWh，实际273天结束在下限。当前λ=0.4125555556不足以让该模型主动维持6000 kWh的目标。软惩罚仅保证偏离有成本，不保证目标可达或被选择；本轮按确认参数保留结果，没有事后调参。

实际控制按参考轨迹追踪，可能在电池仍有空间时弃用富余，也可能在仍有可用电量时保留储备并购买应急电。这些是经济性改进点，不是本次物理约束违反。下一轮应采用同初末条件的对照，评估跨日窗口、末端价值和供需误差风险，而不是将当前费用称为全年最优值。
